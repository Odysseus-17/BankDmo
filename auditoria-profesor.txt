5. FUNCIONALIDADES NUEVAS QUE SE AGREGARON EN LAS CLASES QUE FALTASTE
================================================================

1. Manejo centralizado de errores via @RestControllerAdvice con respuestas
   JSON estandarizadas (timestamp, status, error, message) y manejo
   especifico de errores de validacion (MethodArgumentNotValidException).
2. Capa de servicio con arquitectura interfaz + implementacion (Service /
   Impl), inyeccion por constructor con @RequiredArgsConstructor.
3. Registro de usuario con creacion automatica de cuenta bancaria (saldo
   inicial 1000.00, numero de cuenta generado) dentro de la misma
   transaccion (@Transactional).
4. Autenticacion real con Spring Security usando AuthenticationManager +
   UsernamePasswordAuthenticationToken, en vez de solo comparar
   contrasenas manualmente.
5. JWT completo: generacion de token (JwtTokenProvider.generateToken),
   extraccion de usuario desde el token, validacion de firma/expiracion,
   y un filtro (JwtAuthenticationFilter) que intercepta cada request, lee
   el header Authorization: Bearer ... y setea el SecurityContextHolder.
6. CustomUserDetailsService que conecta tu entidad User con el modelo de
   Spring Security (UserDetailsService).
7. Endpoints REST reales (AccountController) para listar cuentas del
   usuario autenticado y consultar una cuenta especifica, protegidos por
   el usuario logueado extraido del Authentication.
8. Inicio de la logica de transferencias entre cuentas (aunque el
   profesor la dejo a medio hacer: validar cuentas distintas, origen,
   destino, saldo suficiente, actualizar saldos, registrar transaccion -
   solo el primer paso esta esbozado).

7. ERRORES QUE YA EXISTEN EN TU CODIGO ACTUAL (no corregidos aun)
================================================================

dto/request/LoginRequest.java
- Usa @Email, @NotBlank, @Size sin ningun import -> no compila
- @Notblank (con "b" minuscula) no existe como anotacion -> typo

dto/request/RegisterRequest.java
- Solo importa @Email; usa @NotBlank y @Size sin importar
- Mismo typo @Notblank

dto/request/TransferRequest.java
- Cero imports de validacion; usa @Notblank, @NotNull, @Decimalmin
  (deberia ser @DecimalMin) sin importar nada -> no compila

dto/response/TransactionResponse.java
- Sin anotaciones Lombok (@Getter/@Builder), pero se pretende construir
  con builder en el servicio
- Campo declarado como "TransactionType TransactionType" (tipo y nombre
  de campo identicos, mala practica, aunque tecnicamente compila)
- Linea suelta "Private" (con mayuscula, sin tipo ni nombre) al final del
  cuerpo de la clase -> no compila

config/JwtProperties.java y config/SecurtityConfig.java
- Ambas son clases completamente vacias (solo package + public class X {}),
  sin ningun campo ni configuracion

repository/AccountRepository.java
- Metodo findByAccoutNumber (falta la "n" de "Account") - Spring Data JPA
  no podra derivar la consulta correctamente contra el campo real
  accountNumber

repository/TransactionRepository.java
- JPQL roto: "SELECT t FROM Transaction WHERE t.sourceAccoutn.id = :
  accountId OR t.destinationAccount = : accountId ORDER BY t.timestamp DESC"
  - Falta el alias de la entidad (FROM Transaction t, no solo FROM Transaction)
  - Typo sourceAccoutn (deberia ser sourceAccount)
  - Compara t.destinationAccount (una entidad Account) directamente contra
    un Long - deberia ser t.destinationAccount.id
  - Este JPQL no compilara al iniciar la aplicacion (Hibernate falla al
    parsear la query)

pom.xml
- spring-boot-starter-webmvc no es un artifactId real de Spring Boot (el
  correcto es spring-boot-starter-web)
- spring-boot-starter-data-jpa-test, spring-boot-starter-security-test,
  spring-boot-starter-webmvc-test tampoco existen como artifacts -
  normalmente se usa spring-boot-starter-test (scope test) + opcionalmente
  spring-security-test
- Faltan dependencias: JWT (jjwt), validacion (spring-boot-starter-validation),
  driver MySQL (mysql-connector-j) - aunque application.yml ya referencia
  com.mysql.cj.jdbc.Driver

application.yml
- Typo include-mesaage (deberia ser include-message)
- Bloque app.jwt.secret y app.jwt.expiration-ms estan vacios/con
  comentario placeholder, sin valores reales

Nota: dado que pom.xml referencia artifacts inexistentes, es probable que
tu proyecto actualmente ni siquiera compile/descargue dependencias
correctamente. Esto es independiente de si asististe o no a las clases -
es un error de base que conviene corregir primero.
